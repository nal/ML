# CLI Contract

Existing Docker commands and defaults remain valid. `python -m shape_classifier train|evaluate|predict` accept `--device {auto,cpu,mps}` (default `auto`). The resolved environment, device, Python and PyTorch versions are printed at startup; training also reports CPU thread count. Explicit unavailable MPS exits nonzero with an actionable error before checkpoint or results writes. `auto` uses usable MPS only outside Docker.

All commands accessing the same results or checkpoint must be run sequentially, including training, summary, evaluation and prediction. Wait for one command to finish before starting the next; overlapping access is unsupported and need not be detected. `train` retains existing options and adds one completed entry to `<data-dir>/benchmark-results.json`. Its existing paired accuracy output remains. If results cannot be saved, training reports failure and preserves the existing checkpoint. Pending interrupted publication is recovered before subsequent classifier access; inaccessible recovery destinations cause a clear error. Checkpoints retain their existing default path and portable format. `evaluate` and `predict` load compatible old and new checkpoints across devices.

`python -m shape_classifier summary --data-dir PATH` reads the shared results (default `/data`). For each distinct dataset fingerprint, seed, epochs and batch size it prints Docker CPU, native CPU and native MPS rows, including counts, mean warm-up-excluded total and per-epoch training times, held-out per-image inference time, final loss, and both training and held-out accuracy. Missing configurations and unavailable times are explicit. Missing or empty results print `no results yet` and exit zero. Invalid or unsupported results produce a clear error and nonzero exit without mutation. Output includes caveats about small synthetic data, differing device arithmetic and resource allocations, and measured GPU results including slower ones.

Dataset generation retains `python -m shape_dataset --output-dir PATH`. See [data model](../data-model.md) for validation, sequential access, recovery and metric semantics.
