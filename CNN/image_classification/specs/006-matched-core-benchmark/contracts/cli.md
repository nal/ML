# CLI and Results Contract

`python -m shape_classifier train [existing options] [--cpu-threads N]`: N is a positive integer no greater than process-available CPUs. Omission retains feature 004's all-available default. Invalid input fails nonzero, naming requested and available counts for an excessive request, before data loading or checkpoint/results/recovery writes. Startup reports the configured CPU computation pool count and request/default status. Evaluation and prediction retain existing behavior.

For Docker, the documented host launcher queries the selected running Colima profile and matches its reported Docker socket to the effective Docker endpoint before passing an observation to its container invocation. On missing, invalid, unsupported or mismatched evidence, the container records `"unknown"` and warns. A known VM count differing from an explicit thread request produces a warning naming both; training continues if the request is within process availability. A known matching count produces no mismatch warning. No application command modifies the VM. Direct Docker invocation remains supported and can report unknown.

New entries add `requested_cpu_threads` as an integer or null. Legacy entries without the field remain valid and are interpreted as default; see [data model](../data-model.md). The summary command retains its existing interface and groups by actual threads and Docker VM allocation in addition to existing keys. It displays counts and default/explicit/mixed provenance, VM allocation or unknown, and whole-GPU labeling for MPS. It retains paired accuracies, missing configurations and measured values without scaling. Summary does not mutate results. Existing sequential access and transactional recovery contracts remain in force.
